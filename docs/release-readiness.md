# Publication readiness — 2026-10-11

Harbor is a working experimental runner with stronger native evidence on ARM64 than on Intel. It is not ready to claim stable support or safe real-identity migration. The source publication destination is [davetist/harbor](https://github.com/davetist/harbor). Binary builds are published as experimental GitHub prereleases by the workflow below.

## Improvements before stable release

1. Complete native Intel ship execution and valid disposable-key onboarding on every target. Both combined ARM64 candidates passed supplemental stopped-comet lifecycles with all four maintenance commands, export/restore/checkpoint replay, authenticated restarts and another manual restart. The Mac also passed early first-boot shutdown/resume. These are separate trials; [validation](validation.md) records their exact scope and binary hashes. The earlier Pi replay failure was reproduced in an isolated post-replay copy with a traced LMDB/loom collision; eight matched explicit-map starts passed. Adaptive mappings apply to every ship launch and Pack/Meld/Roll/Chop on all four targets: at least twice the largest database's logical size, rounded up to a power of two with a 64 GiB minimum and recalculated before launch. Vere 4.6's `play` and `prep` parsers do not accept that option. Native Mac/Pi folder import, repeated/automatic/post-Pack restart and unsafe-storage refusal passed at 64/128/256 GiB. Larger tests used sparse trailing space on valid copies; populated large-ship workloads and host address-space limits still need acceptance. The policy mitigates the collision but does not fix upstream address ownership. A separate untraced Pi Pack allocator crash remains preserved with its recovery hold and unresolved cause. The [native acceptance tool and four-runner workflow](native-acceptance.md) are prepared; hosted Intel Go checks do not establish native ship acceptance. Real-identity migration remains unvalidated.
2. Exercise physical external storage, disconnect/power/failure behavior and representative active ships. Current thresholds derive from two hardware configurations and an SD-card baseline.
3. Validate the exact [universal macOS disk image](macos-distribution.md) downloaded on a clean Mac, including the documented manual first-launch approval. Distribution intentionally uses no Developer ID signing or notarization. The universal Mac app now creates configuration/services on first launch; Linux desktop `.deb` and headless `.run` installers are built. Managed updates preserve configuration/data and deliberately stopped state. Native Mac/Pi empty-registry install/upgrade/stop/removal trials passed; Mac window/file-picker interaction was inspected. The installed `0.1.0-alpha.4-install.3` Mac app also passed [native close/stop/restart/uninstall menu checks](validation.md#macos-installation-menus--2026-10-11), retaining configuration and a disposable data fixture on removal. The `install.4` disk image passed a [real Safari download and quarantine-command trial](validation.md#macos-browser-download-and-allowance--2026-10-11) on the current Mac, including native launch and a configuration-preserving upgrade. Clean-Mac first installation, public-release download delivery, the Open Anyway alternative, native Intel installer execution, a privileged graphical Debian install/removal and real boot-without-login acceptance remain open. No network self-updater is supplied; updates use a new app download, package upgrade or the newer headless installer with `--upgrade`.
4. Explicit [retention preview/apply controls and logical/allocated disk accounting](retention.md) are implemented and tested. Age thresholds, a minimum of currently integrity-checked exports, a cleanup budget and job/recovery protections apply only with Harbor stopped. Canonical folder aliases share the controller lock. Live quotas and automatic archive eviction remain open. Startup key cleanup now preserves referenced keys.
5. Storage-location clarity is fixed: the host API distinguishes manager `dataDir`, default `pierRoot` and `allowedRoots`. Onboarding uses the permitted pier destination.
6. Keyboard focus, arrow/Home/End tab behavior, tab/panel associations, selected upload mode, contrast and 44px control targets are improved. Automated WCAG checks pass across eight fixture screens at 1280/390/320px and three actual native ship panels at desktop/mobile widths. Actual Dojo/Open interaction and desktop/mobile screenshot inspection pass. Human screen-reader/physical-touch acceptance and other failure/recovery states remain open; this is not a claim of complete WCAG conformance.
7. Failed post-utility restarts persist recovery holds, preventing unattended restart and protecting checkpoints. Private-worker readiness and graceful bootstrap ownership are fixed, with an actual Mac early-signal/resume trial and cancellation/ownership regressions. Expand graceful/forced shutdown, corruption and recovery windows without weakening those holds. A green routine suite does not certify upstream Vere or every OS service-manager outcome.
8. Ephemeral listeners are fixed: port-zero configuration now uses the assigned port for Host validation while preserving wildcard/private-interface rules. Loopback/wildcard regressions and actual native service trials pass.

Readiness checks passed: Go race suite and vet, TypeScript, three frontend unit tests, 21 routine browser tests and a separately executed native browser acceptance test. The two legacy fake-ship live tests were skipped; the new native browser test is also opt-in during ordinary routine runs. The refreshed advisory checks found zero npm advisories and no reachable Go vulnerabilities. The production frontend still emits a chunk-size warning (about 599 kB uncompressed main JavaScript); measure startup on slower devices before deciding whether further splitting is useful.

Revisit the [LMDB mapping workaround and retirement criteria](lmdb-mapping-workaround.md) with each runtime catalog change. Retiring collision mitigation requires a released and natively verified upstream address-ownership fix; removing explicit sizing also requires default-capacity/address-space validation on supported hosts. There is no automatic exemption for a newer version.

No authentication, tunnel, certificate, pairing or mount/formatting subsystem is proposed. The intended deployment remains a trusted LAN plus externally managed Tailscale.

## Build and publish procedure

Run routine checks from CONTRIBUTING.md. Release packaging also needs Python 3. Replace `VERSION` with an unused release version, then run:

```sh
HARBOR_GO=go scripts/build-release.sh VERSION
```

The script refuses an existing version directory, creates only its own temporary staging area, and writes `dist/releases/VERSION/`. It includes four binary archives, two Linux desktop `.deb` packages, two offline headless `.run` installers and an allowlisted source archive. A build on macOS also includes the universal desktop `.dmg`; Linux builds cannot compile the Mac shell. `SHA256SUMS` covers only that version's archives. The Mac app uses local ad-hoc signatures; the script does not notarize or publish artifacts. An existing candidate directory is immutable; choose a new version after reviewing any further changes.

The [**Build and publish install packages** workflow](https://github.com/davetist/harbor/actions/workflows/release-candidate.yml) runs on every push to `main`, including documentation-only commits. Automatic builds use `0.1.0-main.RUN_NUMBER`; manual dispatch still accepts an explicit candidate version. The Linux job cross-builds all four binary archives and both architectures' `.deb` and `.run` installers; a separate macOS job builds the universal Intel/Apple Silicon `.dmg`. Both jobs verify their checksums before uploading temporary artifacts for the publishing job. The Mac artifact contains the disk image and its checksum file; the app remains inside the disk image so download preserves executable permissions and bundle signatures. Each push gets its own run without cancelling earlier package builds.

After both builders pass, the publishing job downloads their outputs, rechecks the checksums, and combines them into one `SHA256SUMS`. It publishes all ten packages and the checksum file to a [GitHub prerelease](https://github.com/davetist/harbor/releases) tagged `vVERSION` at the exact built commit. Release assets have no CI retention expiry and are not automatically deleted. The intermediate CI artifacts retain their 14-day cleanup; that does not remove release downloads. Only the publishing job has repository write permission. Prereleases include the experimental limitations and do not replace a stable release's Latest designation. Reusing an existing release version fails rather than overwriting published assets.

Extract the source archive into a fresh folder, install from its lockfile, rebuild the embedded interface and native binary, run tests, and smoke-test an empty registry with temporary data and loopback ports. Inspect archive contents and notices for missing licenses or private/generated files. Cross-compilation is separate from native ship acceptance.

Review the explicit source allowlist, private reporting, hosted CI and exact release assets. Automated prereleases keep the experimental limitations visible; publication does not establish stable-release readiness. Independently download published packages, verify checksums and repeat the fresh-install flow. Clean-machine download/install acceptance remains outstanding.
