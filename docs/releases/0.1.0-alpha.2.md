# Harbor 0.1.0-alpha.2 — security and recovery

Released 16 October 2026. This experimental alpha includes the security fixes
and recovery improvements since alpha 1 for macOS and 64-bit systemd Linux,
on Intel/AMD and ARM64.

## Changes

- Addresses all 14 findings from the deep security scan, combining overlapping
  issues. Archive parsing and export enforce payload, metadata, path, object,
  allocation and time budgets; restore uses opened directory handles and checks
  disk/inode capacity.
- Strengthens filesystem ownership, native lock and snapshot checks before ship
  and utility launches. Temporary cleanup preserves replacement directories,
  and the optional Mac icon-build recipe uses a private temporary directory.
- Verifies interrupted Stop operations offline when recorded evidence permits.
  Vere inspects an independent copy of the current event store and snapshot;
  any mutation retains the hold. Successful verification leaves the ship stopped.
- Preserves the hostname/IP used to open Harbor in ship links and offers an
  explicit, confirmed interrupt for an unresponsive ship web interface.
  Failed readiness checks retain process ownership and recovery evidence.

## Downloads and upgrades

Download your installer and `SHA256SUMS` from
[this release](https://github.com/davetist/harbor/releases/tag/v0.1.0-alpha.2).
Verify the selected file before opening or running it.

| Host | Installer |
| --- | --- |
| macOS 13+, Apple Silicon or Intel | `Harbor-0.1.0-alpha.2-macos-universal.dmg` |
| Debian/Ubuntu/64-bit Raspberry Pi OS, Intel/AMD | `harbor-0.1.0-alpha.2-linux-amd64.deb` |
| Debian/Ubuntu/64-bit Raspberry Pi OS, ARM64 | `harbor-0.1.0-alpha.2-linux-arm64.deb` |
| Other systemd Linux, Intel/AMD | `harbor-0.1.0-alpha.2-linux-amd64.run` |
| Other systemd Linux, ARM64 | `harbor-0.1.0-alpha.2-linux-arm64.run` |

Follow the [installation and upgrade guide](https://github.com/davetist/harbor/blob/v0.1.0-alpha.2/docs/installation.md#updates-and-removal)
for your existing installation format. CLI/package replacement preserves
configuration, piers and deliberately stopped manager state. Opening the Mac app
or Linux desktop launcher explicitly starts Harbor. Updates are not installed
automatically. macOS still requires manual first-launch approval; Developer ID
signing and notarization are not provided.

Agents should start with the [installation runbook](https://github.com/davetist/harbor/blob/v0.1.0-alpha.2/AGENTS.md#agent-installation-runbook).
Packages need neither Go nor Node. Source builds require Go 1.27.2+, Node 24.x
and Python 3 for packaging/acceptance tooling.

## Validation and limits

The source candidate passed 453 Go tests with the race detector, vet, the
production build, frontend checks and packaging/acceptance contracts. A fresh
Apple Silicon comet passed login, restart, Pack/Roll/Chop, export/restore/replay
and graceful shutdown; the final manifest-parser correction separately passed
fresh export/import, native boot and authenticated login. Interrupted Stop
recovery was tested separately on disposable native Mac and Raspberry Pi
fixtures. Exact candidates and boundaries are recorded in
[validation](https://github.com/davetist/harbor/blob/v0.1.0-alpha.2/docs/validation.md).
Tagged hosted checks and installer builds are available in
[Actions](https://github.com/davetist/harbor/actions).

Use disposable ships while valid identity-key onboarding, real-identity
migration, physical-drive failures, representative large active ships and
broader interruption/recovery acceptance remain open. Native installer execution
on Intel, clean-Mac first installation/manual approval, Meld and runtime
transitions require their own relevant trials. Earlier evidence belongs to its
dated candidate; routine tests and cross-builds do not establish native lifecycle
or installer acceptance. The adaptive LMDB map mitigates an upstream Vere 4.6
address collision; it does not repair corruption or establish an upstream fix.
See [release readiness](https://github.com/davetist/harbor/blob/v0.1.0-alpha.2/docs/release-readiness.md).

Harbor has no separate login: every client reaching its control listener can
manage its ships. Use a trusted LAN/tailnet with external firewall policy.
Windows, 32-bit Linux and non-systemd Linux remain unsupported.

Report security problems through
[private vulnerability reporting](https://github.com/davetist/harbor/security/advisories/new).
Keep keys, codes, cookies, private piers and raw logs out of public reports.
