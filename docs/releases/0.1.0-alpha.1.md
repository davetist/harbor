# Harbor 0.1.0-alpha.1 — first public alpha

Released 13 October 2026. This is Harbor's first named public alpha, following
the automated `main.*` development builds. Harbor is a self-hosted Urbit ship
manager for macOS and 64-bit systemd Linux, on Intel/AMD and ARM64.

## Included

- A universal Mac app and Linux installers with a background runner; closing
  the interface leaves ships running.
- Comet/key onboarding, stopped-pier registration, verified full-pier archives,
  access codes, ship links and a PTY-backed Dojo.
- Pack, Meld, Roll and Chop, editable schedules and measured resource checks.
- Vere updates, replay, durable recovery holds and data-preserving manager
  upgrades/removal.
- HTTP ports chosen at ship startup, user-selected pier folders, storage UUID
  checks, retention controls and installer update discovery.
- An agent installation runbook, current configuration/troubleshooting guidance
  and explicit validation limits.

## Downloads and installation

Download the installer for your host and `SHA256SUMS` from
[this release](https://github.com/davetist/harbor/releases/tag/v0.1.0-alpha.1).
Verify the selected file against its checksum before opening it.

| Host | Installer |
| --- | --- |
| macOS 13+, Apple Silicon or Intel | `Harbor-0.1.0-alpha.1-macos-universal.dmg` |
| Debian/Ubuntu/64-bit Raspberry Pi OS, Intel/AMD | `harbor-0.1.0-alpha.1-linux-amd64.deb` |
| Debian/Ubuntu/64-bit Raspberry Pi OS, ARM64 | `harbor-0.1.0-alpha.1-linux-arm64.deb` |
| Other systemd Linux, Intel/AMD | `harbor-0.1.0-alpha.1-linux-amd64.run` |
| Other systemd Linux, ARM64 | `harbor-0.1.0-alpha.1-linux-arm64.run` |

On Mac, drag Harbor into Applications and open it. Developer ID signing and
notarization are not provided; macOS may require **Privacy & Security → Open
Anyway**, or the documented Harbor-only quarantine command.

On Debian-based Linux, use `sudo apt install ./ACTUAL.deb`, then launch Harbor
or run `harbor install` as the ordinary service user. For the standalone format,
run `sh ACTUAL.run` as that user. Administrator approval installs system files
and enables startup without login. Both Linux formats include the CLI and
desktop launcher; a normal systemd user session is required.

Existing users should follow the
[upgrade procedure](https://github.com/davetist/harbor/blob/v0.1.0-alpha.1/docs/installation.md#updates-and-removal)
for their original installation format. Preserve configuration, piers and
deliberately stopped services through the CLI/package replacement path. Opening
the Mac app or Linux desktop launcher explicitly starts Harbor. The Harbor footer can offer automated `main.*`
prereleases as well as named alphas; update checks never install software.

Agents should begin with
[AGENTS.md](https://github.com/davetist/harbor/blob/v0.1.0-alpha.1/AGENTS.md#agent-installation-runbook).
Installed packages need neither Go nor Node. Source builds require Go 1.27.2+
and Node 24.x; Python 3 supports packaging and native acceptance tooling.

## Validation and alpha limits

The exact checks, native trial results and remaining gates are recorded in
[validation](https://github.com/davetist/harbor/blob/v0.1.0-alpha.1/docs/validation.md)
and [release readiness](https://github.com/davetist/harbor/blob/v0.1.0-alpha.1/docs/release-readiness.md).
Routine tests and cross-builds are distinct from real ship and installer trials.

Fresh comet onboarding, authenticated login, stop/start, Pack/Roll/Chop,
export/restore and replay passed on all four native macOS/Linux ARM64/x86_64
targets in the [release lifecycle run](https://github.com/davetist/harbor/actions/runs/38387194232).
The local alpha runner also passed the Apple Silicon lifecycle and a disposable
Mac service install/upgrade/stop/start/removal trial. All 66 browser checks were
exercised: 61 fixtures and five separately enabled native checks for filesystem
browsing, Dojo, ship links, accessibility, schedules and real update discovery.
Go race/vet, frontend type/unit, package/acceptance-contract and dependency
advisory checks passed.

Use disposable ships while valid identity-key onboarding, real-identity
migration, physical-drive failure recovery and representative large active-ship
workloads remain unvalidated. Earlier ARM64 trials covered all four maintenance
commands, export/restore/replay and authenticated restarts; broader interruption
and recovery windows remain open. The adaptive LMDB map is an upstream Vere 4.6
collision mitigation, not an address-ownership fix. An earlier untraced Pi Pack
crash remains a preserved historical failure with unresolved cause.

Clean-Mac first installation/manual approval, native Intel installer execution,
Intel Meld and large-map workloads, physical power/disconnect failures and human
screen-reader/touch acceptance remain separate gates. Passing a disposable
service trial or routine tests does not close those gates.

Harbor has no separate login. Every client that can reach its control listener
can manage all registered ships. Use a trusted LAN/tailnet with external firewall
policy; do not publish the control or ship ports. DNS/mDNS/Tailscale hostname
access requires the matching `advertisedHost` configuration. Windows, 32-bit
Linux and non-systemd Linux are unsupported.

Report reproducible bugs through
[GitHub issues](https://github.com/davetist/harbor/issues), including version,
platform, expected behavior and a redacted reproduction. Use
[private vulnerability reporting](https://github.com/davetist/harbor/security/advisories/new)
for security problems. Do not attach keys, codes, cookies, private piers or logs.
